# Wi-Fi 与安卓版本说明

本次直接修改了原目录 `C:\Users\Administrator\Downloads\ethertransfer-master` 的源码，保留现有汉化界面和有线传输实现。原 `publish` 目录内的旧版本没有替换；请运行本次输出的新电脑端。

## 使用

1. 主机、笔记本使用新的 Windows 版本；安卓手机安装 EtherTransfer-Android.apk（Android 8.0 及以上）。
2. 手机与电脑连接同一 Wi-Fi，保持软件打开。电脑可以同时保留直连笔记本的网线。
3. Windows 首次运行时允许防火墙联网。左侧“已发现的设备”自动列出运行 EtherTransfer 的设备，并显示“有线”或“Wi-Fi”。它不会列出没有运行此软件的路由器、电视等设备。
4. 手机先点击“选择接收文件夹”，通过系统文件选择器授权一个可写目录。每次接收创建独立的 EtherTransfer-时间戳 子目录。
5. 电脑向手机发送文件或文件夹：电脑添加内容、选手机、发送，手机确认接收。
6. 手机向电脑发送文件：手机添加文件、点选电脑、发送，电脑确认并选择保存目录。支持多文件及整个文件夹；点击“添加文件夹”，进入目标文件夹后点击系统的“使用此文件夹”并授权。
7. 手机传输时保持应用在前台和屏幕亮起。本版未实现后台服务及断点续传。

## 实现

- 发现广播、来源网段校验、网络变化监听同时覆盖物理以太网与 Wi-Fi，继续排除虚拟网卡与 VPN 网卡。
- 按网卡实际 IPv4 掩码匹配地址，不再将 TCP 绑定判断写死成 /24；实测网络为 /15。
- 每个设备保存不同网卡的地址，按会话合并显示并优先选有线路径；拔掉网线不再直接取消正在进行的无线 TCP 传输。
- 安卓端使用系统原生 Java API，无第三方运行时库，只有 Wi-Fi 网络入口。
- 安卓实现既有 EtherTransfer V1：UDP 50000 发现、长度前缀 JSON、原始 TCP 文件流和 FOLDER_BEGIN 文件夹流。
- 接收前确认、路径校验、接收临时文件、中断清理及独立目录，避免覆盖已有文件。
- 修复电脑端接收确认阶段的探测读取未退出就开始正式读取的竞争。

## 构建与测试

电脑端需要 .NET 10 SDK：

```powershell
dotnet build EtherTransfer.UI -c Release
dotnet publish EtherTransfer.UI -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:PortableBuild=true
```

安卓端使用本机现有 JDK 21、Android SDK，无须安装 Gradle：

```powershell
.\EtherTransfer.Android\build.ps1
.\EtherTransfer.Android\test.ps1
```

两个脚本中的 SDK/JDK 路径对应本机安装位置，换电脑时调整这两个路径。APK 使用本地开发签名，`build/development.p12` 不纳入源码包；公开发行前应使用独立私密的发布密钥。

`test.ps1` 运行 Java 编解码自检和完整 .NET 测试，包含 Java/C# 双向文件及文件夹协议互通。只运行 `dotnet test` 时，5 项依赖 Java 的互通用例会提示跳过；通过 `test.ps1` 运行不跳过。

## 当前边界

- 使用原软件的明文局域网 TCP 协议，没有新增 TLS 或设备身份认证。接收设备名称可被同网段设备冒充，只在可信局域网中确认接收。
- Wi-Fi 访客网络、AP 隔离或拦截 UDP 广播的网络可能阻止发现；没有手动 IP 或中继回退功能。
- 不支持手机后台常驻、断点续传、跨公网、iPhone；未承诺无线与有线之间无缝续传。
- 手机发送前将所选文件暂存到应用缓存，需有足够剩余空间；结束会清理暂存文件。
- 收到的文件夹保留内容与路径，安卓端未保留 Windows 文件时间戳。可发送整个空文件夹；源协议没有内部空子目录条目，因此内部不含文件的子目录不会重建。


## 安卓 0.2.0 界面更新

- 蓝白卡片界面、附近设备选中样式、在线数量、文件名称预览与固定发送按钮。
- 在“准备发送”卡片右上角点击“清空选择”，一次移除所有待发送文件；原文件不会删除。
- 没有选文件或正在传输时，“清空选择”不可用；传输中也不能添加文件、更换设备或更改保存目录。
- 本机名称卡片可以点开修改；接收文件夹显示当前保存路径。
- 向下滚动可查看接收目录、进度与取消操作。


## 安卓 0.3.0：发送整个文件夹

- “准备发送”卡片新增“添加文件夹”。可以多次添加，也可以和文件混合选择；重复选择同一文件夹不会重复加入。
- 点击后使用安卓系统文件夹选择器：进入要发送的文件夹，点“使用此文件夹”，再允许读取。
- 发送包括文件夹下的文件和含文件的子目录，保留中文路径、目录结构和空文件；整个空根文件夹也可以发送。
- “清空选择”同时移除文件及文件夹选择，原内容不删除；传输时禁用添加和清空。
- 系统限制选择手机存储根目录、Download 根目录或 Android/data 等位置时，请进入一个普通子文件夹再选择。
- 发送前会把所选内容暂存到应用缓存，需要足够手机剩余空间；无权限读取的内容会报错并中止，不会静默漏发。
- 不需要更换现有电脑端。本版沿用 FOLDER_BEGIN 和文件夹二进制流；内部空子目录及文件时间戳受旧协议/手机元数据支持限制。


## 0.3.1 多设备与快速重启修复

主机、笔记本都需要使用 0.3.1 电脑版，手机安装 0.3.1 APK。关闭旧版及旧的传输结果窗口后运行新版；Windows 弹出联网权限时允许局域网访问。

- 取消通过当前 TCP 连接传递，电脑端不再广播取消通知，也不响应旧版的全网取消广播。
- 设备具有稳定 DeviceId，每次启动仍生成独立 SessionId。重启后的新会话替换旧会话，迟到的旧下线通知不能删除新记录。
- 设备列表刷新保留选中目标，支持同名的不同设备。
- 设备发现回复仅从匹配目标网段的网卡发出，避免泄露不匹配网卡的地址。
- 每台设备同一时间处理一项传输；忙碌时向第三台明确回复“设备正在处理另一项传输”，不会覆盖当前接收/进度窗口。

有线与 Wi-Fi 都发现设备但连接超时时，还需要确认接收端防火墙允许该版本，以及 Wi-Fi 没有客户端隔离。
